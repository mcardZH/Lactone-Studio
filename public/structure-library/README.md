# SciYue 常用结构库

这是随软件离线提供的精选建模来源，不是数据库镜像，也不是已替用户完成的新计算。实际条目以各类别的 `manifest.json` 为准。

## 分类与文件

`metals`、`nonmetals`、`metal-oxides`、`nonmetal-oxides`、`semiconductors`、`two-dimensional`、`mof`、`cof` 分别保存金属、非金属、两类氧化物、半导体、二维材料、MOF 和 COF。

每条结构集中在自己的 ASCII 目录：`structure.json` 为程序读取的完整晶胞及笛卡尔坐标，`source.cif` 为可追溯的 CIF 来源或明确注明转换方法的 CIF。来源原本是 CONTCAR、FHI-aims geometry 等格式时，另保留原始文件；不能把转换后的 CIF 当成原始下载字节。索引记录来源 ID、版本、文献、许可、模型类型和实际规范化步骤。

## 来源和使用边界

- 实验、公开计算、数据库整理和由已知结构派生的模型分别标识；同一名称不代表所有晶相、堆垛、客体、缺陷或氢定位方式。
- COD 数据沿 CC0 1.0 来源声明；CoRE、QMOF、Materials Cloud 或作者公开数据按每条记录的实际许可及版本保存，并保留所需署名/引文。不同数据库或同名数据库的其他版本不能自动套用本条许可。
- 整理或优化模型不冒充原始实验 CIF。尤其 UiO-66 的 CoRE 含氢初始模型保留其上游整理氢位置，不宣称这些氢为实验精修定位；具体边界见该条来源说明。
- 二维条目明确保留源结构和派生步骤、面内周期轴及真空间隙。二维模型身份不等于当前 xTB 已支持真二维量化边界。
- 未知电荷/自旋和缺少可靠带隙不猜测、不填零。库中参考物性属于原条目的来源，不会自动变成编辑后模型的计算结果。
- 预览连接在独立显示副本中沿公共经验规则生成；不会改写原始坐标、文件或当前工作区。载入默认建立新模型，后续修改由模型历史管理。

只纳入能可靠追溯和读取的有序模型；部分占位、无法确定的化学身份或不明许可候选不通过自动补位/补氢变成正式条目。结构查看/周期编辑的本轮上限为 10,000 原子；科学后端仍各自遵守其原有资源和准入限制。
